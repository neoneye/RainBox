# Launcher Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement `docs/superpowers/specs/2026-09-10-launcher-design.md` phase 1: a stdlib-only `source/launcher.py` that starts the core and the enabled static services as siblings, reconciles against `GET /services/api/desired`, reports to `POST /services/api/status`, and is controlled from `/settings` toggles and Restart buttons.

**Architecture:** A data-only catalogue (`services/definitions.py`) is imported by both the launcher and the core. The core registers `services.<key>.enabled`, `services.<key>.env.<VAR>` and internal `services.<key>.restart_nonce` settings from it, serves the desired snapshot (only when started with the launcher's instance markers), and keeps launcher status in memory. The launcher is a single-threaded loop over monotonic deadlines: reap, reconcile, stop/escalate, backoff, poll, heartbeat, two-phase shutdown.

**Tech Stack:** Python 3 stdlib only in the launcher (`subprocess`, `http.client`, `fcntl`, `signal`, `selectors`); Flask + settings registry in the core; pytest.

## Global Constraints

- Work from `source/`; core tests `venv/bin/python -m pytest -q <path>`; the launcher tests spawn real child interpreters from a temporary catalogue and a fake in-process core — no real services.
- `launcher.py` and `services/definitions.py` import only the standard library (a test asserts it).
- Children: `Popen(..., cwd=…, env=…, start_new_session=True, shell=False, stdin=DEVNULL, close_fds=True)`; never `preexec_fn`, never fork without exec.
- No credential value ever appears in the desired-state response, status, argv, logs, or the database.
- Commit per task; messages end with the Co-Authored-By trailer; PII sweep before push.

## Tasks

1. **Catalogue + settings registration.** `services/__init__.py` (docstring only), `services/definitions.py` (`ServiceKind`, `STATIC_SERVICES`, `SCHEMA_VERSION`, `BASELINE_ENV_KEYS`), settings entries generated in `db/settings.py`, `db/test_settings_services.py`.
2. **Core-side registry + API.** `services/registry.py` (`desired_snapshot()`, `set_service_setting()`, `bump_restart_nonce()`, in-memory `LauncherStatus`), `webapp/services_api.py` (`GET /services/api/desired`, `POST /services/api/status`, `GET /services/api/status`, `POST /services/api/restart/<key>`), registered in `webapp/__init__.py`; `webapp/test_services_api.py`.
3. **Launcher core loop.** `launcher.py`: args, state dir + lock, credentials parser, env construction, HTTP client with elapsed-time bound, desired validation, process records, reconcile, backoff, exit-code mapping, group stop/escalate, two-phase shutdown, status posting; `test_launcher.py` with fake core + temp catalogue children.
4. **Settings page.** Observed state + Restart per `services.<key>.enabled` card, a launcher card (managed/unmanaged, core state, Restart core), marker tests in `webapp/test_settings_views.py`.
5. **Repo integration.** `.gitignore` `var/services/`, `.env.example` note, `README.md` layout row, `main.py` echo of instance markers is implicit (env), run all touched suites, sweep, push branch.
