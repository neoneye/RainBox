# Launcher Implementation Plan

**Status:** implemented on the `launcher` branch (2026-09-10), against
`docs/superpowers/specs/2026-09-10-launcher-design.md`. The tasks below are
the work as it stands; the last section records what was built first and
then abandoned, and why, so the history behind the current shape is not
lost when someone reads the code.

**Goal:** A stdlib-only launcher, `source/main.py`, is the way rainbox
starts: it runs the core (`source/core.py`, the former `main.py`) and the
side services enabled on `/settings` as sibling processes, keeps them
running, stops what is disabled, restarts on request, and reports what it
sees — without polling anything.

**Architecture:** A data-only catalogue (`services/definitions.py`) is
imported by both the launcher and the core; it is the only place that says
which services exist, where they live, and which environment variables they
may be given. The core registers `services.<key>.enabled`,
`services.<key>.env.<VAR>` (typed) and internal `services.<key>.restart_nonce`
settings from it. Launcher and core talk over one `socketpair()` the core
inherits as `core.py --control-fd N` — the mechanism the core already uses
for its agents. Both directions are pushes of JSON lines: the core sends a
desired-state snapshot at startup and whenever a `services.*` setting or
nonce changes; the launcher sends its status table whenever a process
changes. The launcher is one single-threaded loop asleep in `select()` on
that socket and its signal pipe; it wakes for a line, for `SIGCHLD`, for a
shutdown signal, or for one of its own deadlines (stop escalation, backoff
retry, group drain, shutdown phase, inactivity log). EOF on the socket is
liveness in both directions.

**Tech Stack:** Python 3 stdlib only in the launcher (`subprocess`, `socket`,
`select`, `fcntl`, `signal`); Flask + the settings registry in the core;
pytest with real child interpreters and a fake core on a socketpair.

## Global Constraints

- Work from `source/`; core tests `venv/bin/python -m pytest -q <path>`; the
  launcher tests spawn real child interpreters from a temporary catalogue
  and hold the other end of the control socketpair — no real services.
- `main.py` and `services/definitions.py` import only the standard library
  (a test asserts the module set).
- Children: `Popen(..., cwd=…, env=…, start_new_session=True, shell=False,
  stdin=DEVNULL, close_fds=True, pass_fds=(control fd,) for the core)`;
  never `preexec_fn`, never fork without exec.
- A service child's environment is built from scratch: a baseline (`PATH`,
  `HOME`, `LANG`, `LC_*`, `TMPDIR`), the catalogue-approved values, and at
  most one credential. `PYTHONPATH`, `DATABASE_URL`, and loader-injection
  variables never pass through.
- No credential value ever appears in a snapshot, a status line, argv,
  logs, or the database.
- Commit per task; messages end with the Co-Authored-By trailer; PII sweep
  before every push.

## Tasks (as implemented)

1. **Catalogue + settings registration.** `services/__init__.py`,
   `services/definitions.py` (`ServiceKind`, `EnvVar`, `STATIC_SERVICES`,
   `SCHEMA_VERSION`, baseline env keys, exit codes 2 and 3), settings
   entries generated in `db/settings.py` (typed env overrides with
   validation, so an invalid edit is refused before any restart),
   `db/test_settings_services.py`.
2. **Core side.** `services/registry.py`: `desired_snapshot()` from one
   statement over the settings table; `set_service_setting()` (row lock,
   stage value and nonce, one commit, then push); `bump_restart_nonce()`;
   `ControlChannel` (attach the inherited fd, push snapshots, reader thread
   for status lines, EOF → unmanaged); `LauncherStatus`. `core.py` takes
   `--control-fd`. `webapp/services_api.py` keeps only what the page needs:
   `GET /services/api/status` and `POST /services/api/restart/<key>`.
   `webapp/test_services_api.py` holds the other end of the socketpair.
3. **Launcher loop.** `main.py`: args (`--state-dir`, `--core-only`), state
   dir with an exclusive lock (`launcher.lock`, exit 3 if held), the
   `credentials.env` grammar, environment construction, bind-probe port
   check, the control channel (spawn the core with `--control-fd`, read
   snapshot lines, push status lines, drop the channel on EOF or a failed
   send), snapshot validation, process records, reconcile, backoff and
   crash budget, exit-code mapping, process-group stop and escalation,
   two-phase shutdown (services first, core last; a second signal kills
   every owned group), non-blocking status sends with backpressure, child
   stdout/stderr piped and printed with a `[<key>] ` prefix, and the
   inactivity log at 1, 10, 60 minutes, then hourly. `test_main.py` covers all of it with a fake core on a socketpair
   and real fake-service children, including a real fake core child that
   speaks the protocol for the shutdown test.
4. **Settings page.** A launcher card (managed or unmanaged, core state,
   Restart core) and, on each `services.<key>.enabled` card, the observed
   state and a Restart button; marker tests in
   `webapp/test_settings_views.py`.
5. **Repo integration.** `var/services/` ignored; `.env.example` explains
   launcher-only credentials; `README.md` describes both files; the rename
   of `launcher.py` to `main.py` and `main.py` to `core.py`, with every
   reference in code, docs, and notes updated; `RAINBOX_CORE_PORT` so a
   second core can run beside the operator's for a smoke test.

## Verification

- Suites: 41 tests across `test_main.py` and `webapp/test_services_api.py`;
  62 across `test_core.py`, `test_env_file.py`, `db/test_settings*.py`,
  `webapp/test_settings_views.py`; pyright clean on `main.py`, `core.py`,
  `services/registry.py`, `webapp/services_api.py`.
- Live: the launcher ran the real core (`--core-only`, sandbox database, a
  spare port). Status arrived over the socket; Restart core through the API
  replaced the core, and the new core received the full table right after
  its first snapshot; SIGTERM ran both shutdown phases with nothing left.
- Idle cost, `top` per process on macOS (context switches per 30 s as the
  wakeup count, %CPU over 60 s): launcher 8 switches and 0.07 CPU-seconds
  in 153 s; the core under it 167 switches at 0.02 %, inside the range the
  core shows on its own (144–194, 0.09–0.14 %).

## Approaches tried and abandoned

Each of these was implemented, tested, and in most cases measured before
being replaced. They are recorded here because the current code is shaped
by what they got wrong.

### HTTP polling as the control plane

**What it was.** The launcher was an HTTP client of the core: every 5 s it
fetched `GET /services/api/desired` and every 30 s it posted its status
table to `POST /services/api/status`; the core marked observed state
`unknown` after 90 s without a post. To make sure a snapshot came from the
core this launcher had spawned and not from an unrelated core on the same
port, the launcher generated `RAINBOX_LAUNCHER_ID` and
`RAINBOX_CORE_INSTANCE_ID`, passed them in the core's environment, and
required every response and post to echo them. The client went through
three revisions: `http.client`, then a raw-socket HTTP/1.1 client because
`http.client` bounded only each socket read and a trickling header could
stall the single-threaded loop, then hardening of that client's chunked
decoding (a signed chunk size walked the cursor backwards forever) and
`Content-Length` handling (short bodies and negative lengths were accepted).

**Why it was abandoned.** Two reasons, one measured and one structural.
Measured: seven Flask requests per 30 s — a session, a `SELECT`, JSON each —
roughly doubled the core's idle CPU (0.25 % against 0.09–0.14 % alone) and
added about 77 context switches per 30 s to a process whose idle is the
baseline this project protects, paid whether or not any service was
enabled. Structural: every piece of the design existed to compensate for
polling — the markers to authenticate a response, the heartbeat and its
90-second staleness rule to infer liveness, the deadline-bounded HTTP
client and its parsers to keep a bad peer from stalling supervision — and
each grew its own class of bugs. A socketpair the core inherits gives
identity (only that child holds the fd), liveness (EOF), and push in both
directions for free, so the whole layer disappeared. A toggle now applies
in milliseconds instead of within 5 s.

### A fixed 0.25-second loop timer

**What it was.** The first loop called `select()` with a constant
quarter-second timeout, so an idle launcher woke four times a second to
find nothing to do: 160 context switches per 30 s.

**Why it was abandoned.** It was exactly the idle wakeup this project is
meant to avoid. The intermediate fix made the timeout the time to the
earliest real deadline and let `SIGCHLD` wake the loop for child exits (36
switches per 30 s, most of them the HTTP polls). The socket channel then
removed the polls too, leaving 8.

### A port probe before spawning the core

**What it was.** First a connect probe: the launcher connected to
`127.0.0.1:5000` and refused to start if anything answered. Then a bind
probe: it attempted the same `SO_REUSEADDR` bind the core makes and refused
if that failed.

**Why both were abandoned.** The connect probe refused to start on every
Mac with AirPlay Receiver on, because ControlCenter answers loopback
connects on `*:5000` while the core's `127.0.0.1:5000` bind succeeds beside
it. The bind probe fixed that but was still a time-of-check/time-of-use
race against the core's own bind a moment later, and a speculative refusal
is worse than a clean failure. Now there is no probe: the core binds first
thing in `main()` and exits with code 3 when the address is in use, which
the launcher reports as `failed` without a respawn loop.

### Dropping the channel when a status send blocked

**What it was.** A status line the core did not take within a 2-second
socket timeout closed the control channel.

**Why it was abandoned.** The channel is an inherited socketpair and cannot
be reopened, so a transient stall in the core — a long garbage collection,
a blocking query — would have left a healthy core permanently unmanaged
until its next restart. Sends are now non-blocking with a pending line, the
socket joins `select()`'s write set, a newer table replaces a pending one
whose bytes have not gone out, and only a peer that is actually gone closes
the channel.

### The launcher reading the repo-root `.env`

**What it was.** The first design had the launcher parse `.env` itself to
resolve a bridge's credential by name.

**Why it was abandoned** (at design review, before implementation). It
would have meant a second dotenv parser with subtly different semantics,
and `.env` is loaded by every process that builds an LLM, so bridge-only
credentials do not belong there anyway. The launcher reads a private
`<state-dir>/credentials.env` with a deliberately small grammar; `.env`
stays the core's.

### `launcher.py` beside `main.py`

**What it was.** The launcher was first added as `launcher.py` next to the
existing `main.py`.

**Why it was abandoned.** The launcher is the primary way to start rainbox,
so it took the `main.py` name and the former entrypoint became `core.py`,
the name every design document already used for that process.
